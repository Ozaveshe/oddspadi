## Batch 1 — Timezone & hydration correctness (24 issues)

Every timestamp the product renders was formatted with `toLocale*` and no pinned
`timeZone`, so it resolved against the render host's zone — UTC on Netlify. For a
fixtures product built for a West-Africa audience that showed every kickoff, engine
run and settlement an hour or more off. In client components that server-render, the
same call also produced a genuine hydration desync (server says UTC, browser says
local), which several call sites were papering over with `suppressHydrationWarning`
— that hides the warning but freezes the wrong server text on screen.

`LocalTime` already existed and solved this properly (deterministic UTC first paint,
post-mount re-format in the visitor's zone) but was used in only one place.

| # | File | Issue | Fix |
|---|------|-------|-----|
| 1 | `components/odds/LocalTime.tsx` | Only two format variants and no null/invalid-input handling, so most call sites could not adopt it | Added `seconds`/`date`/`daymonth`/`weekday` variants, nullable `iso`, a `fallback` prop, a `LocalTimeText` variant for contexts that cannot nest `<time>`, and pinned the deterministic pass's locale as well as its zone |
| 2 | `components/live/MatchdayFallback.tsx` | Server component rendered kickoff times in the host zone | Renders through `LocalTime` |
| 3 | `components/live/LiveTicker.tsx` | Kickoff chip desynced on hydration, masked by `suppressHydrationWarning` | Renders through `LocalTimeText`; suppression removed |
| 4 | `components/live/LiveScoreBoard.tsx` | Upcoming-fixture kickoff cell had the same masked desync | Renders through `LocalTimeText` |
| 5 | `components/live/LiveScoreBoard.tsx` | `dayLabel` let the locale float, so server (`en-US`) and browser (`en-GB`) produced different text | Pinned `Intl.DateTimeFormat` with explicit locale + UTC |
| 6 | `components/live/LiveScoreBoard.tsx` | "Updated HH:MM:SS" stamp formatted in the host zone | Renders through `LocalTimeText variant="seconds"` |
| 7 | `components/odds/IntelligenceSlate.tsx` | Provider "Last run" in host zone | `LocalTime` |
| 8 | `components/odds/IntelligenceSlate.tsx` | Decision "Generated" stamp in host zone | `LocalTime` |

| 11 | `components/odds/IntelligenceSlate.tsx` | Homepage engine-status "Last run" in host zone | `LocalTime` |
| 12 | `components/odds/AgentReport.tsx` | Notebook `nextReviewAt` in host zone | `LocalTime` |
| 13 | `components/odds/AgentReport.tsx` | Monitoring-plan `nextReviewAt` in host zone | `LocalTime` |

| 20 | `app/predictions/history/page.tsx` | Ledger "Updated" and per-row "Settled" in host zone | `LocalTimeText variant="datetime"` |
| 21 | `app/predictions/decision-engine/page.tsx` | Last-run stamp in host zone | `LocalTime variant="datetime"` |
| 22 | `app/predictions/[matchId]/page.tsx` | Decision clock, "Decision generated" and "Price expires" in host zone; `shortDate` could slide a head-to-head date by a day | `LocalTime` for the three stamps, pinned UTC formatter for `shortDate` |
| 23 | `app/community/u/[handle]/page.tsx`, `app/predictions/league/[slug]/table/page.tsx` | Published-tip date and table `updatedAt` in host zone | `LocalTime` / `LocalTimeText` |
| 24 | `components/community/CommunityFeed.tsx`, `PostComments.tsx` | `ago()` duplicated verbatim in two files; computed `Date.now()` during render so the server's minute count was frozen into the DOM by `suppressHydrationWarning`, and the label never ticked | Extracted `components/community/RelativeTime.tsx` with a deterministic first paint and a one-minute tick; both call sites now share it |

**Regression guard:** `src/test/server-rendered-timezone.test.ts` walks `src/app` and
`src/components` and fails on any date-shaped `toLocale*` call that does not pin
`timeZone`, with `LocalTime` itself as the single documented exemption.
