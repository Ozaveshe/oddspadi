## Batch 1 — Timezone & hydration correctness (24 issues)

Every timestamp the product renders was formatted with `toLocale*` and no pinned
`timeZone`, so it resolved against the render host's zone — UTC on Netlify. For a
fixtures product built for a West-Africa audience that showed every kickoff, engine
run and settlement an hour or more off. In client components that server-render, the
same call also produced a genuine hydration desync (server says UTC, browser says
local), which several call sites were papering over with `suppressHydrationWarning`
— that hides the warning but freezes the wrong server text on screen.

`LocalTime` already existed and solved this properly (deterministic UTC first paint,
post-mount re-format in the visitor's zone) but was used in only one place.

| # | File | Issue | Fix |
|---|------|-------|-----|
| 1 | `components/odds/LocalTime.tsx` | Only two format variants and no null/invalid-input handling, so most call sites could not adopt it | Added `seconds`/`date`/`daymonth`/`weekday` variants, nullable `iso`, a `fallback` prop, a `LocalTimeText` variant for contexts that cannot nest `<time>`, and pinned the deterministic pass's locale as well as its zone |
| 2 | `components/live/MatchdayFallback.tsx` | Server component rendered kickoff times in the host zone | Renders through `LocalTime` |
| 3 | `components/live/LiveTicker.tsx` | Kickoff chip desynced on hydration, masked by `suppressHydrationWarning` | Renders through `LocalTimeText`; suppression removed |
| 4 | `components/live/LiveScoreBoard.tsx` | Upcoming-fixture kickoff cell had the same masked desync | Renders through `LocalTimeText` |

## Batch 2 — SEO (27 issues)

The headline defect: Next merges metadata shallowly, so any page that does not
declare its own `openGraph` inherits the root layout's **entire** block — including
`url: siteUrl`. Eleven routes were therefore telling every search and social crawler
that their `og:url` was the homepage. A new `lib/seo/pageMetadata.ts` builds a
self-referencing canonical, `og:url` and Twitter card from one input, and the root
layout no longer declares a `url` for anything to inherit.

## Batch 3 — API security & hardening (13 issues)

The headline defect: three public routes accepted an unvalidated `date` query
parameter that is simultaneously a CDN cache key (`Netlify-Vary: query=date`) and an
upstream provider fan-out key. The only check was a format regex, which admits about
three million distinct `YYYY-MM-DD` strings plus impossible ones like `2026-99-99`.
A single client walking dates could therefore mint unbounded edge-cache entries and
unbounded provider calls against a metered quota.

| # | File | Issue | Fix |
|---|------|-------|-----|
| 52 | `app/api/sports/_utils.ts` | `parseSportsQuery` checked date *shape* only — `2026-02-30` and `9999-12-31` both passed through to the provider | `parseIsoDateParam()` verifies a real calendar date and bounds it to ±400 days of today |
| 53 | `app/api/live/route.ts` | `date` went straight from the query string to the provider and to the CDN cache key with no validation at all | Routed through `parseIsoDateParam`, 400 on anything outside the window |
| 54 | `app/api/sports/fixtures/route.ts`, `live-scores/route.ts` | Same unbounded key space via `parseSportsQuery` | Fixed at the shared parser |
| 55 | `app/api/sports/_utils.ts` | `parsePredictionFilters` returned unbounded strings that reach query builders and `ilike` patterns | Capped at 120 characters |
| 56 | `lib/sports/intelligence/auth.ts` | `parseRequestedSports` split the raw parameter before validating anything, so an oversized value built a large array first | Length-capped ahead of the split; the supported set is hoisted out of the function |
| 57 | `lib/security/boundedJson.ts` | `request.text()` buffers the entire body *then* measures it. The declared-length guard it was paired with is skipped simply by omitting `Content-Length`, so a chunked body was fully materialised in function memory before rejection | Streams the body and aborts the moment the running byte count passes the limit |
| 58 | `lib/security/privateJson.ts` (new) | Session-scoped **reads** returned no cache directive and no `Vary` — mutations set `private, no-store` but the reads that expose the viewer's likes, poll choice, team search and own posts did not | `privateJson()` helper emitting `private, no-store` + `Vary: Cookie` |
| 59 | `app/api/community/*/route.ts` (8 routes) | As above, on every community read/write response | All `Response.json` calls routed through `privateJson` |
| 60 | `app/api/account/*/route.ts` (4 routes) | As above, on profile, teams, followed-teams and push-subscription | All routed through `privateJson` |
| 61 | `app/api/health/route.ts` | Not wrapped in `withApiHandler`, so a throw from the Supabase runtime probe crashed the endpoint uptime monitors poll | Wrapped; its test updated for the now-async handler |
| 62 | `next.config.mjs`, `netlify.toml` | No `Strict-Transport-Security` — the first request of a session could be downgraded to HTTP before the redirect landed | Two-year HSTS with `includeSubDomains; preload` in both configs |
| 63 | `next.config.mjs`, `netlify.toml` | No `Cross-Origin-Opener-Policy`, so a popup could reach back through `window.opener` | `COOP: same-origin` and `CORP: same-site` in both configs |
| 64 | `next.config.mjs`, `netlify.toml` | The two header sets had drifted apart with no test binding them | The new suite asserts both configs carry the same transport headers |

**Regression guard:** `src/test/api-hardening.test.ts` (16 tests) covers the date
window, the sports-parameter cap, the streaming body cap including the
missing-`Content-Length` case, the private-cache contract, a sweep asserting no
account/community route still calls bare `Response.json`, and header parity between
the two deploy configs.

## Batch 4 — Accessibility (8 issues)

The headline defect: the live surfaces poll every 45–60 seconds and re-render their
whole subtree each time, and three of those subtrees were marked `aria-live="polite"`
— the entire match list, the entire 14-chip ticker, and the "Updated HH:MM:SS" clock.
A screen reader therefore read the whole board *and* a ticking clock aloud on every
poll, in perpetuity. That is worse than no live region at all: it makes the page
unusable rather than accessible.

| # | File | Issue | Fix |
|---|------|-------|-----|
| 65 | `components/live/LiveScoreBoard.tsx` | The whole `.match-list` was a live region, re-announced every 45s | `aria-live` removed |
| 66 | `components/live/LiveTicker.tsx` | The whole `.ticker` was a live region, re-announced every 60s | `aria-live` removed; kept named via `role="group"` |
| 67 | `components/live/LiveScoreBoard.tsx` | The auto-refresh clock was a live region, so the time was announced every 45s | `aria-live` removed — a clock is not an announcement |
| 68 | `components/live/ScoreAnnouncer.tsx` (new) | Removing the above would have left no announcements at all | A single `sr-only` region that fires only when a scoreline actually changes, silent on first paint, and capped at four fixtures so a burst of simultaneous goals cannot flood the queue |
| 69 | `components/share/ShareBar.tsx` | `aria-label` on a plain `<div>` — with no role to attach to, assistive technology discards it and the share cluster was announced unnamed | Added `role="group"` |
| 70 | `components/live/LiveTicker.tsx` | Same unnamed-container problem on the ticker | Added `role="group"` |
| 71 | `components/site/SiteNav.tsx` | `aria-controls="mobile-more-menu"` pointed at a node that only exists while the sheet is open — a dangling IDREF whenever it is closed | Reference is conditional on the sheet being mounted |
| 72 | `app/page.tsx`, `components/community/FeedComposer.tsx` | The "how it works" `<ol>` exposed decorative step numerals, so screen readers announced "1, 1. Scan the full schedule"; the composer's character counter was not associated with its textarea | `aria-hidden` on the numerals; `aria-describedby` + a polite counter on the composer |

**Regression guard:** `src/test/live-board-accessibility.test.ts` fails if the bulk
containers or the clock regain `aria-live`, if the dedicated announcer is unmounted,
or if an `aria-label`led `<div>` appears without a role.

with nothing catching a rejection. `fetch` rejects on a dropped connection, an offline
tab or an abort — and when it does, every statement after it is skipped, including the

| 78 | `components/odds/TipsSharePreview.tsx` | `navigator.clipboard.writeText` was awaited unguarded; a denied clipboard permission raised an unhandled rejection for a cosmetic action | try/catch |
| 79 | `components/odds/TipsSharePreview.tsx` | The "Copied" reset timer was never retained or cleared — setState after unmount, and two quick clicks raced two timers so the first cleared the second's toast early | Timer held in a ref, cleared on unmount and before rescheduling |

## Batch 6 — Backend / library correctness (9 issues)

The headline defect: the Slip Check measured a slip's edge against the **vigged**
price. The engine's own published formula — stated in `decisionModelMathProof.ts` and
`decisionModelCards.ts` — is `edge = modelProbability - noVigProbability`, and every
slip leg already carried the no-vig figure the engine computed for it. That field was
captured and then never read. Using `1 / combinedOdds` instead folds the bookmaker's
margin into the model's favour on every leg and compounds it across the slip.

| # | File | Issue | Fix |
|---|------|-------|-----|
| 83 | `lib/sports/betSlip.ts` | The probability gap was measured against the vigged price, overstating the model's own edge by roughly the compounded per-leg margin | Gap now measured against the no-vig parlay probability each leg already carries |
| 84 | `components/odds/SlipCheckClient.tsx` | The verdict copy presented that inflated gap as the model's advantage | Reports model chance, fair-market chance and the vigged price separately, and names the difference as the bookmaker's margin |
| 85 | `lib/sports/betSlip.ts` | `noVigProbability` was declared `number` but never validated on read, so a corrupt or hand-edited `localStorage` entry put a string or `NaN` into a typed numeric field | `isProbability` guard in `isSlipLeg`, exercised against `readSlip` in the tests |
| 86 | `lib/sports/homepageState.ts` | When the engine returned no fixtures the homepage fell back to live-board coverage but still labelled the source "Prediction engine" — crediting the engine for coverage it did not produce, on a product whose pitch is transparency | Label reflects the source actually in use |
| 87 | `lib/sports/homepageState.ts` | Raw status enum tokens (`unavailable`, `partial`, `empty`) were rendered under a "Provider health" label | Mapped to human copy |
| 88 | `app/news/rss.xml/route.ts` | Slugs are database values interpolated **raw** into `<link>` and `<guid>` while only title/excerpt/category were escaped — one `&` in one slug produced malformed XML and broke the whole feed for every subscriber | Percent-encoded and XML-escaped through a shared helper |
| 89 | `app/news/rss.xml/route.ts` | An unparseable `publishedAt` emitted a literal `Invalid Date` into `<pubDate>` | Falls back to the build time |
| 90 | `app/news/rss.xml/route.ts` | No `<lastBuildDate>`, so readers could not distinguish a stale feed from a fresh one | Added |
| 91 | `app/news/feed.json/route.ts` | Item `id`/`url` interpolated the slug unencoded, so a slug containing a space, `#` or `?` produced a URL resolving somewhere else | Percent-encoded via `absoluteUrl` |

**Regression guard:** `src/test/syndication-feeds.test.ts` renders both feeds against
hostile slugs and dates; `src/test/bet-slip.test.ts` gained cases pinning the fair-price
benchmark and the storage guard.

## Round two — batches 8–18 (issues 101–200)

A second pass over the areas round one did not reach: the scheduled Netlify
functions, the settlement and training pipelines, the stylesheet, the ops scripts,

### Batch 8 — Scheduled functions & error reporting (11 issues)

The push sweep could not complete at any real scale. Its dedupe check ran *inside*
the subscription × fixture loop as a separate awaited round-trip: 1,000 subscribers
and 50 candidate fixtures is up to 50,000 sequential queries inside a function whose
wall-clock budget is measured in seconds.

| # | File | Issue | Fix |
|---|------|-------|-----|
| 101 | `netlify/functions/push-notification-worker-background.ts` | Three unbounded `select`s (subscriptions, follows, teams) | Explicit per-sweep ceilings that fail visibly rather than timing out |
| 102 | same | N×M sequential dedupe queries — the sweep could not finish | One ledger read per sweep |
| 103 | same | The delivery-ledger insert result was discarded. That row is the only thing preventing the notification going out again, so a failed write meant the same push every ten minutes — counted as a successful send | Failure is counted as a failure |
| 104 | same | No behavioural test coverage at all | Five tests, including one asserting the ledger is read exactly once |
| 105–108 | `push-notification-sweep`, `editorial-generation-sweep`, `weekly-results-recap`, `model-learning-sweep` | Returned the worker's `Response` object straight through, forwarding every upstream header into the scheduled-function reply. | 114 | `lib/sports/training/historicalIngestion.ts` | Suspended matches entered the **training corpus** as completed results | `"suspended"` added to the guard |
| 115 | same | Any explicitly supplied unrecognised status was silently coerced to `"finished"` | Now a caller error; an *absent* status still defaults to finished |
| 116 | `netlify/functions/push-notification-worker-background.ts` | Filtered on `"not_started"`, `"ft"`, `"completed"` — none of which the normalised column can hold | Dead entries removed |

### Batch 12 — Undeclared CSS custom properties (6 issues)

An undefined `var()` makes the declaration invalid *at computed-value time*, which is
not the same as being ignored: the property falls back to its initial value and still
wins the cascade. `background: var(--undefined)` does not leave the previous
background in place — it renders transparent.

### Behaviour changes worth calling out

Three fixes change what the product *says*, not just how it is built. Each replaced a
statement that was factually wrong:

1. **Slip Check** now measures edge against the fair (no-vig) price. Displayed
   probability gaps will be **smaller** than before — the previous figures credited the
   model with the bookmaker's margin.
2. **The homepage** no longer attributes live-board fallback fixtures to the prediction
   engine, and shows readable provider-health copy instead of raw enum tokens.
3. **Kickoffs and engine timestamps** now render in the visitor's timezone rather than
   the deploy host's (UTC), so displayed times will shift for anyone outside UTC.
4. **Suspended fixtures no longer settle.** Community tips on a suspended match now
   wait, then go to manual review, instead of paying out on the interrupted scoreline.
   Some tips that would previously have been marked won/lost will sit unsettled.
5. **`?sport=cricket|rugby|handball` now returns 400** instead of an empty 200. These
   were already disabled in the UI, but any caller relying on the empty response will
   see the error.
6. **Won-result dots are visible again** on the results record strip — they had been
   rendering transparent, so that strip will look different (correct) after deploy.
