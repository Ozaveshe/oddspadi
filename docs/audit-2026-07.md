## Batch 1 — Timezone & hydration correctness (24 issues)

Every timestamp the product renders was formatted with `toLocale*` and no pinned
`timeZone`, so it resolved against the render host's zone — UTC on Netlify. For a
fixtures product built for a West-Africa audience that showed every kickoff, engine
run and settlement an hour or more off. In client components that server-render, the
same call also produced a genuine hydration desync (server says UTC, browser says
local), which several call sites were papering over with `suppressHydrationWarning`
— that hides the warning but freezes the wrong server text on screen.

`LocalTime` already existed and solved this properly (deterministic UTC first paint,
post-mount re-format in the visitor's zone) but was used in only one place.

| # | File | Issue | Fix |
|---|------|-------|-----|
| 1 | `components/odds/LocalTime.tsx` | Only two format variants and no null/invalid-input handling, so most call sites could not adopt it | Added `seconds`/`date`/`daymonth`/`weekday` variants, nullable `iso`, a `fallback` prop, a `LocalTimeText` variant for contexts that cannot nest `<time>`, and pinned the deterministic pass's locale as well as its zone |
| 2 | `components/live/MatchdayFallback.tsx` | Server component rendered kickoff times in the host zone | Renders through `LocalTime` |
| 3 | `components/live/LiveTicker.tsx` | Kickoff chip desynced on hydration, masked by `suppressHydrationWarning` | Renders through `LocalTimeText`; suppression removed |
| 4 | `components/live/LiveScoreBoard.tsx` | Upcoming-fixture kickoff cell had the same masked desync | Renders through `LocalTimeText` |
| 5 | `components/live/LiveScoreBoard.tsx` | `dayLabel` let the locale float, so server (`en-US`) and browser (`en-GB`) produced different text | Pinned `Intl.DateTimeFormat` with explicit locale + UTC |
| 6 | `components/live/LiveScoreBoard.tsx` | "Updated HH:MM:SS" stamp formatted in the host zone | Renders through `LocalTimeText variant="seconds"` |
| 7 | `components/odds/IntelligenceSlate.tsx` | Provider "Last run" in host zone | `LocalTime` |
| 8 | `components/odds/IntelligenceSlate.tsx` | Decision "Generated" stamp in host zone | `LocalTime` |

| 11 | `components/odds/IntelligenceSlate.tsx` | Homepage engine-status "Last run" in host zone | `LocalTime` |
| 12 | `components/odds/AgentReport.tsx` | Notebook `nextReviewAt` in host zone | `LocalTime` |
| 13 | `components/odds/AgentReport.tsx` | Monitoring-plan `nextReviewAt` in host zone | `LocalTime` |
| 14 | `components/odds/AgentReport.tsx` | Task `dueAt` in host zone | `LocalTimeText` |

| 21 | `app/predictions/decision-engine/page.tsx` | Last-run stamp in host zone | `LocalTime variant="datetime"` |
| 22 | `app/predictions/[matchId]/page.tsx` | Decision clock, "Decision generated" and "Price expires" in host zone; `shortDate` could slide a head-to-head date by a day | `LocalTime` for the three stamps, pinned UTC formatter for `shortDate` |

| 24 | `components/community/CommunityFeed.tsx`, `PostComments.tsx` | `ago()` duplicated verbatim in two files; computed `Date.now()` during render so the server's minute count was frozen into the DOM by `suppressHydrationWarning`, and the label never ticked | Extracted `components/community/RelativeTime.tsx` with a deterministic first paint and a one-minute tick; both call sites now share it |

**Regression guard:** `src/test/server-rendered-timezone.test.ts` walks `src/app` and
`src/components` and fails on any date-shaped `toLocale*` call that does not pin
`timeZone`, with `LocalTime` itself as the single documented exemption.

## Batch 2 — SEO (27 issues)

The headline defect: Next merges metadata shallowly, so any page that does not
declare its own `openGraph` inherits the root layout's **entire** block — including
`url: siteUrl`. Eleven routes were therefore telling every search and social crawler
that their `og:url` was the homepage. A new `lib/seo/pageMetadata.ts` builds a
self-referencing canonical, `og:url` and Twitter card from one input, and the root
layout no longer declares a `url` for anything to inherit.

| # | File | Issue | Fix |
|---|------|-------|-----|
| 25 | `app/layout.tsx`, `lib/seo/pageMetadata.ts` | Root `openGraph.url` inherited by 11 routes, each claiming to be the homepage | Dropped `url` from the root block; added a shared `pageMetadata()` builder |
| 26 | `app/about/page.tsx` | No social card — shares fell back to the generic site card | `pageMetadata()` with a page-specific card |
| 27 | `app/community/page.tsx` | No social card | `pageMetadata()` |
| 28 | `app/predictions/page.tsx` | No social card | `pageMetadata()` |
| 29 | `app/predictions/tomorrow/page.tsx` | No social card | `pageMetadata()` |
| 30 | `app/privacy/page.tsx` | No social card | `pageMetadata()` |
| 31 | `app/terms/page.tsx` | No social card | `pageMetadata()` |
| 32 | `app/season-outlooks/page.tsx` | No social card | `pageMetadata()` |
| 33 | `app/news/page.tsx` | No social card | `pageMetadata()`, preserving the feed `alternates.types` |
| 34 | `app/predictions/league/[slug]/table/page.tsx` | No social card | `pageMetadata()` |
| 35 | `app/predictions/league/[slug]/table/page.tsx` | An unknown slug 404s but returned a bare indexable title — a crawlable soft 404 | Returns `robots: { index: false, follow: false }` |
| 36 | `app/news/[slug]/page.tsx` | Article `openGraph` declared no `url`, so news stories emitted no `og:url` at all | `pageMetadata({ type: "article" })` |
| 37 | `app/news/[slug]/page.tsx` | A missing story returned `{}` — inheriting the root card as a soft 404 | Explicit noindex fallback |
| 38 | `app/news/[slug]/page.tsx` | `NewsArticle` and `BreadcrumbList` hardcoded `https://oddspadi.com`, so preview and staging deploys published structured data pointing at production | Derived from `NEXT_PUBLIC_SITE_URL` via `absoluteUrl()` |
| 39 | `app/news/[slug]/page.tsx` | `NewsArticle` had no `publisher.logo` or `image`, which makes it ineligible for Google's article rich result regardless of the rest | Added both, plus `inLanguage` and an `@id`-shaped `mainEntityOfPage` |
| 40 | `app/sitemap.ts` | `getNewsStories()` was awaited unguarded while fixtures were carefully timeout-wrapped — one editorial outage failed the entire sitemap | Wrapped in the same `withTimeout` guard |
| 41 | `app/sitemap.ts` | `/predictions/today`, `/predictions/tomorrow` and `/predictions/week` were absent — three of the highest-intent routes on the site | Added |
| 42 | `app/sitemap.ts` | The 2,000-entry cap `break`s only the inner loop, so the second day's fixtures kept appending past the limit | Labelled break exits both loops |
| 43 | `app/robots.ts` | `/offline` (service-worker shell) and `/tips` (alias) were crawlable; no `host` declared | Disallowed both, added `host` |
| 44 | `app/offline/page.tsx` | No metadata export at all — the offline shell was indexable and read as a soft 404 | Title, description and explicit noindex |
| 45 | `app/tips/page.tsx` | `redirect()` emits a **307**, telling crawlers `/tips` is still canonical and leaving it competing with `/predictions/today` | `permanentRedirect()` (308) plus noindex |
| 46 | `app/manifest.ts` | `theme_color` and `background_color` were near-black (`#0a0e0c`) on a white site, contradicting the layout's `themeColor: #ffffff` — installed users got a black splash then a black title bar over a white page | Both set to `#ffffff` |
| 47 | `app/manifest.ts` | No `id`, so any later `start_url` change would register as a different app and orphan installed users; no `scope`, `lang`, `dir` or `orientation` | All added |
| 48 | `app/layout.tsx` | RSS/JSON feed autodiscovery lived in `metadata.alternates`, which every page replaces wholesale with its own canonical — the links reached no rendered page | Emitted as real `<link rel="alternate">` tags in `<head>` |
| 49 | `app/layout.tsx` | Organization `logo` was an SVG (rich results need a raster) and `sameAs` shipped as an empty array | Raster `ImageObject` logo; empty `sameAs` dropped |
| 50 | `app/layout.tsx` | `WebSite` and `Organization` were two unlinked nodes | Stable `@id`s, `WebSite.publisher` referencing the Organization, `inLanguage` |
| 51 | `app/community/u/[handle]/page.tsx` | Every tipster profile shared the literal title "Community profile" — identical tabs, history entries and share cards site-wide | `generateMetadata` with a per-handle title, description and canonical |

**Regression guards:** `src/test/page-metadata-seo.test.ts` asserts the canonical/`og:url`
contract, that every route declares metadata with a canonical or an explicit noindex,
and that the root layout never reintroduces an inheritable `openGraph.url`.
