# Canonical market ontology

*Definitions: [`canonicalMarkets.ts`](../src/lib/markets/canonicalMarkets.ts).
Key grammar: [`canonicalKey.ts`](../src/lib/markets/canonicalKey.ts).
Database mirror: `op_canonical_markets`, generated by
[`canonicalSeed.ts`](../src/lib/markets/canonicalSeed.ts).*

## What was wrong

Market identity was bookmaker display text. In `src/lib/sports/types.ts` it is
a flat string union with the line baked into the name:

```
over_under_25  over_under_45  over_under_505
over_under_545 over_under_55  over_under_585  over_under_65
```

Seven members for one market, and every new line was a new member. Worse,
`spread`, `set_handicap` and `total_games` carried **no line at all** — a
basketball spread decision never recorded the number it was taken against.

So an Asian handicap was not merely unmapped, it was unrepresentable. `home
-0.25` had nowhere to live. That is the real reason those decisions could only
ever reach `needs_review`: not a missing rule, a missing dimension.

## The grammar

Two levels. A market key names what is bet on; a selection key names one
outcome within it.

```
market key:     <sport>.<family>.<period>
selection key:  <market key>.<selection>[.<line>]
```

```
football.1x2.regulation.home
football.asian_handicap.regulation.home.-0_25
football.total_goals.regulation.over.2_5
basketball.moneyline.full_game_incl_ot.home
basketball.moneyline.regulation.home
tennis.match_winner.full_match.player_a
```

The decimal point becomes `_` and the sign is preserved: `-0_25`, `2_5`, `0`.

**Overtime lives in the period segment**, not its own. A segment that is
mandatory for basketball and meaningless for tennis cannot be parsed without
first knowing the sport; folding it into the period keeps the grammar
context-free at no cost to what it carries.

**A fifth segment that is not a line is rejected**, not discarded. Dropping it
silently is how `-0.25` becomes `0`.

## What a definition declares

| Field | Values |
|---|---|
| `basis` | `regulation`, `including_extra_time`, `including_shootout`, `full_game_including_ot`, `regulation_excluding_ot`, `sets`, `games`, `match_award` |
| `overtimeRule` | `excluded`, `included`, `not_applicable` |
| `pushRule` | `exact_line_push`, `half_line_no_push`, `quarter_line_half_push`, `no_push` |
| `voidRule` | `void_on_no_result`, `void_on_abandonment`, `settle_if_awarded` |
| `retirementRule` | `settle_on_award`, `void`, `not_applicable` |
| `lineGranularity` | `none`, `integer`, `half`, `quarter` |

Every one is a closed union, so an unhandled case is a compile error rather
than a default. A default here is a wrong verdict on a real claim.

Each definition also carries `settlementBasisStatement` — the basis in plain
language, for operators and analysts. `market-settlement-rules.md` is generated
from those statements rather than restating them.

## Why definitions live in code

Every field above is settlement semantics. Settlement semantics that can be
edited as data can be changed between a publication and its result with nothing
between the edit and the record. A pull request is the review step.

`op_canonical_markets` is a **read-only mirror**, populated by migration with
`insert`/`update`/`delete` revoked from every role including the service key.
It exists so the mapping workbench can join impact queries in SQL against the
largest tables rather than paging them into memory.

Two tests keep the arrangement honest:

- **Mirror parity** regenerates the seed from the registry and compares it
  byte-for-byte with the committed migration. A rule change without a
  regenerated seed fails the build.
- **Declaration parity** exercises each declared rule against a result built to
  trigger it. A market declaring `overtime: excluded` that reads the extra-time
  score fails here — a disagreement that would otherwise be invisible while
  every other test passed.

## Versions are append-only

You never edit `2026-08-07.1`. A change to settlement meaning adds `.2` and
leaves `.1` in the registry, so a settlement recorded against `.1` stays
resolvable forever.

This is what makes "historical records cannot be silently remapped" true at the
definition layer. The alias layer handles the same problem for provider text;
see [provider-market-mapping.md](provider-market-mapping.md).

## Adding a market

1. Add the definition to `CANONICAL_MARKETS` with all rules declared.
2. Implement its grade function in [`grade.ts`](../src/lib/settlement/grade.ts).
3. `npm run docs:canonical-seed` to regenerate the mirror.
4. Add cases to `settlement-fixture-suite.test.ts`. Declaration parity will
   already be exercising the new rules; the suite is for the specific scores
   that make them concrete.
